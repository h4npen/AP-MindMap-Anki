# CMMI（能力成熟度モデル統合）：ピラミッドで覚える「開発組織のオトナ度」

> **想定読者**: 「CMMI」「共通フレーム」など似たようなカタカナ用語の区別がつかず、試験でいつも迷ってしまう文系受験者  
> **省いたもの**: カーネギーメロン大学の歴史、細かいサブカテゴリ分類  
> **所要時間**: 6分  
> **対象過去問**: 応用情報技術者 平成29年秋期 午前問49（※過去問道場で2回間違えた重要問題）  

---

## 0. 一枚で：英語の頭文字で一発暗記！

CMMIの正体を解く鍵は、アルファベットの **「M」** にあります。

```
C M M I
  │
  └─★ M aturity（マチュリティ ＝「成熟度・オトナ度」）！
```

問題文の中に **「プロセスの【成熟度】を評価する」** という日本語が出てきたら、100% CMMIのことです！

---

## 1. 5段階のオトナ度ピラミッド（段位認定）

CMMIは、開発チームが「個人の気合（属人化）」から「組織的なデータ経営」へとステップアップしていく階段を5段階で表したものです。

```
【レベル5：最適化】    データをもとに、作業手順自体を自動で改善し続ける
         ▲
【レベル4：定量管理】  「バグ率0.01%以下」など、数字で品質を管理している
         ▲
【レベル3：定義済み】★ 会社全体で「統一マニュアル（標準レシピ）」がある（最頻出！）
         ▲
【レベル2：管理された】 プロジェクト単位で、店長が計画・進捗を管理している
         ▲
【レベル1：初期段階】   スーパー職人の勘と気合頼み（その人が倒れたら終わり）
```

試験で特によく問われるのは **レベル3（定義済み）** です。  
「個人の頭の中ではなく、**組織全体で標準化されたマニュアル（標準プロセス）が文書化されている状態**」を指します。

---

## 2. ライバル用語との見分け方（超頻出！）

試験の選択肢で必ず CMMI と一緒に並べられて受験生を惑わすのが **「共通フレーム（SLCP）」** です。

| 用語 | 日常のたとえ | 要するに何？（試験の決定打） |
| :--- | :--- | :--- |
| **CMMI** | **「学校の通信簿・段位認定」** | **開発組織の【成熟度】を評価・改善するモノサシ** |
| **共通フレーム** | **「作業手順書・共通語辞典」** | **発注者と受注者で「要件定義」「設計」などの作業範囲や言葉のズレをなくす共通ルール** |

---

## 3. 実際の過去問で腕試し

### 【午前過去問】平成29年秋期 午前問49
**【問題】**  
CMMIの説明はどれか。

- **ア**: ソフトウェア開発組織及びプロジェクトのプロセスの成熟度を評価するためのモデルである。
- **イ**: ソフトウェア開発のプロセスモデルの一種である。
- **ウ**: ソフトウェアを中心としたシステム開発及び取引のための共通フレームのことである。
- **エ**: プロジェクトの成熟度に応じてソフトウェア開発の手順を定義したモデルである。

<details>
<summary>正解とスピード解法を表示</summary>

**正解: ア**

**文系目線でのスピード解法:**
- 「CMMI」の `M` ＝ **Maturity（成熟度）**！
- 選択肢を見ると、アにだけ **「プロセスの成熟度を評価するためのモデル」** とバッチリ書かれています！
- ちなみに **ウ** はライバルの「共通フレーム」の説明です。
</details>
